◉ सुरु गर्ने तरिका

  1. ZIP फाइललाई एउटै folder मा पूर्ण रूपमा extract गर्नुहोस्।
  2. Extract भएको folder भित्रको index.html खोल्नुहोस्।
  3. file:// बाट खोल्दा browser ले folder अनुमति मागेमा “फाइल स्वतः खोज्नुहोस्” प्रयोग गरी सोही folder छान्नुहोस्।

सामान्य local कामका लागि Internet आवश्यक पर्दैन। Firebase realtime sync प्रयोग गर्दा भने Internet चाहिन्छ।

मितिमिति छान्दा सम्बन्धित दैनिक webpage खुल्छ। मिति item दैनिक HTML सँग link गरिएको हुन्छ।
ALLछानिएको महिनाका सबै दैनिक मुख्य content कालक्रमअनुसार एउटै scrollable view मा देखिन्छ।
नयाँ दैनिक फाइलनयाँ filename लाई मुख्य index.html को sibling manifest मा link गरेपछि dropdown ले त्यसलाई चिन्छ।

⇩ Filter तथा Output

  • Input table paste गरेपछि judge वा आवश्यक filter छान्नुहोस्।
  • “श्रीमान् छनोट गर्नुहोस्” को तलको Filter Causelist Tables & Rows खोल्दा चयन गरिएको न्यायाधीशका Table 1, Table 2… स्वतः देखिन्छन्। प्रत्येक table मा ALL+, ALL, ALL- र Custom dropdown हुन्छ; default ALL हो। ALL+ ले table का सबै rows राख्छ, ALL- ले table तथा सोसँग मात्र सम्बन्धित इजलास/न्यायाधीश header हटाउँछ, र Custom मा क, ग, २, ४ जस्ता serial comma ले छुट्याएर लेख्नुहोस्।
  • Output मा छानिएको judge सँग सम्बन्धित आवश्यक विवरण मात्र राखिन्छ।
  • ALL mode मा अन्तिम column को “हेर्न नभ्याइने”, “हेर्न नमिल्ने” वा “स्थगित” row output मा समावेश हुँदैन। ALL+ ले सबै content र Custom ले user ले स्पष्ट छानेका rows राख्छ। Output summary मा बाँकी rows को संख्या देखिन्छ।
  • आवश्यकतानुसार HTML/TXT/DOCX तथा index JSON download प्रयोग गर्नुहोस्।

✎ नेपाली अदालती आदेश/फैसला

  1. दैनिक table मा सम्बन्धित row को “आदेश बनाउनुहोस्” खोल्नुहोस्।
  2. कागजातको प्रकार र पक्षहरूको हैसियत जाँच्नुहोस्। श्रीमान्, मुद्दा नम्बर, मिति र पक्षको नाम source row बाट स्वतः आउँछन्।
  3. तलको preview भित्र नै आदेश वा फैसलाको व्यहोरा सिधै लेख्नुहोस् वा paste गर्नुहोस्।

SUBMIT ले हालको preview user name र timestamp सहित shared history मा राख्छ। प्रत्येक user का पछिल्ला २ वटा submission मात्र global FIFO नियममा रहन्छन्; तेस्रो submission आएपछि सो user को सबैभन्दा पुरानो submission हट्छ। सबै connector का बाँकी submitted file साझा compare सूचीमा देखिन्छन्। COMPARE मा ठीक २ वटा file छानेपछि पुरानो last edited time भएको file “Original” र नयाँ file “Latest” हुन्छ। line break भएको भाग line-wise, अन्य भाग sentence-wise चिनाइन्छ; व्यापक परिवर्तन मात्र पूरै अनुच्छेद पहेँलो हुन्छ। Floating “Files” menu का checkbox बाट filename सहित ठीक २ file छानिन्छन् र Comments पनि floating panel मा खुल्छ, त्यसैले comparison area दुवै file ले पूरा उपयोग गर्छ। Default मा Latest file अक्षरशः intact राखी सबै inline changes Original मा देखिन्छन्; “Vice versa” ले Original intact राखी changes Latest मा सार्छ। सम्भव भएसम्म sentence भित्र बदलिएको word मात्र रातो strike र नयाँ word “+” सहित देखिन्छ; असुविधाजनक परिवर्तनमा मात्र sentence/paragraph fallback हुन्छ। Comparison engine मा उन्नत नेपाली प्रूफरीडरको smart sentence mapping, Nepali normalizer, merge/split detection, punctuation/minor/substantive classification, mapping confidence र १० भन्दा बढी छुट्टाछुट्टै change-region हुँदा sentence fallback समायोजन गरिएको छ। Floating Comments भित्र summary, search र “मूल परिवर्तन / सूक्ष्म / विरामचिह्न / प्रूफरीड” filters उपलब्ध छन्। Latest submitted text मा दोहोरिएको शब्द, punctuation spacing, multiple spaces, देवनागरी पूर्णविराम, अदृश्य Unicode र सामान्य सम्भावित हिज्जे जाँच गरी छुट्टै ✓ प्रूफरीड सुझाव देखिन्छ। Change comment click/keyboard बाट सम्बन्धित inline स्थानमा focus हुन्छ। Go to Top ले preview को माथिल्लो भागमा पुर्‍याउँछ र location icon भएको Pick from where you left ले सुरक्षित cursor राखी त्यसै बिन्दुमा smooth auto-scroll गर्छ। सबै floating icon black/white छन् र Resume/Top, Save/Copy, download/print तथा Submit/Compare को workflow क्रममा राखिएका छन्। फैसला preview मा “इति संवत्…” अब “कम्प्युटर अपरेटर-” को ठीक मुनि आउँछ। कागजातको प्रकार, पक्षहरूको हैसियत वा सामान्य/Partial reverse/Full reverse परिवर्तन गर्दा preview को user-edited मुख्य व्यहोरा जस्ताको तस्तै रहन्छ र placeholder/default content मा फर्किँदैन। Icon हरू सानो बनाइएका छन्। Floating Tools बाट cursor वा selected line/paragraph मा Ascend indent (tab घटाउने), Descend indent (tab थप्ने), bullet हटाउने/थप्ने र subbullet घटाउने/थप्ने सुविधा छ। Ascend वा Descend गर्दा विद्यमान bullet/subbullet यथावत् रहन्छ। Bulleted line को अन्त्यमा Enter थिच्दा समान bullet र indent सहित अर्को item स्वतः तयार हुन्छ। Continuous slider ले ९–२४ pt सम्म सम्पूर्ण preview को text size बदल्छ (default १३ pt)। यी tab, bullet, subbullet र text size DOCX download मा पनि यथावत् रहन्छन्।

↻ Firebase Realtime Sync

  1. बायाँ तलको “Realtime Sync” button खोल्नुहोस्। आफ्नो नाम लेखी पहिलो device मा “नयाँ code” थिच्नुहोस्।
  2. देखिएको ३-अङ्कको passkey अर्को device मा नामसहित राखेर “Connect” थिच्नुहोस्। एउटै passkey मा अधिकतम ४ connector मात्र जोडिन सक्छन्।
  3. अब main form, filtered output, editable आदेश/फैसला preview र submitted history realtime sync हुन्छन्।
  4. “Connector chat” बाट सोही passkey मा जोडिएका user बीच text chat र file attachment पठाउन सकिन्छ; सन्देश/attachment बढीमा ९ घण्टा मात्र रहन्छ। Paperclip बाट बढीमा ५ MB file छानिन्छ। Chat मा extension सहित attached file को original नाम देखिन्छ र त्यसमा click गर्दा त्यही नाममा तुरुन्त download हुन्छ। Chat default dark mode मा खुल्छ र ☾/☀ बाट dark/light बदल्न सकिन्छ। दुवै दिशाबाट आउने नयाँ remote message मा in-page notification र unread badge देखिन्छ; 🔔 बाट browser notification अनुमति दिए system notification पनि आउँछ। Chat सधैँ नयाँ message तर्फ auto-scroll हुन्छ। Message box text अनुसार auto-wrap/auto-grow हुन्छ र सानो arrow button ले send गर्छ। Sender को message receiver device मा पुगेपछि ✓ र receiver ले chat खोली पढेपछि ✓✓ देखिन्छ।
  5. काम सकिएपछि “Disconnect” थिच्नुहोस्। पछिल्लो code यही browser मा मात्र सम्झिइन्छ।
Case-wise previewहरेक “आदेश बनाउनुहोस्” row को preview छुट्टै key मा राखिन्छ; एउटा मुद्दाको व्यहोरा अर्को मुद्दामा मिसिँदैन।
Offline fallbackFirebase वा network उपलब्ध नभए local editing, Save, Copy र downloads पुरानै तरिकाले चलिरहन्छन्।
File uploadBrowser security का कारण selected local file का bytes sync हुँदैनन्। File बाट पढिएको source text भने form state सँग sync हुन्छ।
Last-write winsदुवै device मा एउटै field एकैपटक बदल्दा अन्तिम Firebase update देखाइन्छ।
Shared submissionएउटा connector ले SUBMIT गरेको file अर्को connector को COMPARE सूचीमा पनि तुरुन्त देखिन्छ।
Connector limitTransaction-based slot ले एउटै passkey मा बढीमा ४ सक्रिय user मात्र स्वीकार गर्छ।

यो login-विहीन code-based sync हो। Sync code विश्वासिलो व्यक्तिसँग मात्र बाँड्नुहोस् र Firebase Realtime Database rules उपयुक्त राख्नुहोस्।

  • दैनिक फाइल: indexyyyymmdd.html
